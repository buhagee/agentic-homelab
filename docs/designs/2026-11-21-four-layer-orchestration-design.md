## Problem Statement

We want an open-source, harness-agnostic multi-agent coding orchestrator (`bolt-control`, targeting OpenCode v2 first and extensible to Claude Code, Codex CLI, and Cursor) that combines the strongest open-source methodologies without overlap or wasted ceremony:
1. **Adaptive Front-Door Routing (Layer 0):** Not every task needs 70k tokens of product/architecture ceremony. An adaptive composer scores request entropy and selects the minimum viable workflow tier (from a 1-file inline fix up to a multi-worktree Bolt wave).
2. **Stack & Domain Loadout Injection (Cross-Layer):** Automatically detects the repo's tech stack, project practices (`AGENTS.md`, `docs/practices/`), required domain/stack skills, and live documentation MCPs (`context7`, `academic-papers`, `searxng`) and injects a scoped loadout into each unit's planning, implementation, and review context.
3. **Upfront Product & Architecture Design (Layer 1 — Gstack):** Interactive product framing, scope challenge, and architecture lock (`/gstack-office-hours`, `/gstack-plan-ceo-review`, `/gstack-plan-eng-review`).
4. **Unit DAG, Wave 0 Contracts & Bolt Schedule (Layer 2 — AWS AI-DLC):** Decomposes approved architecture into a cycle-free YAML unit dependency DAG (`units-generation`), freezes shared interfaces/types in a Wave 0 Contract scaffold (`contract-design`), and sequences parallel Bolt waves (`delivery-planning`).
5. **Hands-Off Parallel Worktree Execution (Layer 3 — Mission Control + Superpowers):** Spawns isolated git worktrees and background sessions per unit, assigns per-role/per-task models (`ModelMatrix`), isolates ports/DBs/env per worktree, enforces live `touchSet` and immutable-test guards, requires research before escalating, and routes genuine product/contract blockers into a non-blocking human inbox (`bc_report(status: "blocked")` -> `bc_answer`) while sibling worktrees keep running.
6. **Fresh-Context Spec-Drift & QA Audit (Layer 4 — Superpowers Reviewer + Gstack QA):** Runs an independent fresh-context spec-drift check against the frozen unit spec, chains `/gstack-review`, `/gstack-qa-only`, `/gstack-verify`, and `/gstack-document-release`, records compound wave learnings, and pauses at the owner merge/PR gate.

## Architecture & Lifecycle Overview

```text
[Layer 0: Bolt Composer (`bc_compose` / `/bolt`) — AI-DLC 5-Axis ARS Scorer + Stack Detector]
  Scores: Intent Ambiguity (IAE) | Structural Uncertainty (CSU) | Verification Entropy (VE) | Blast Radius (R) | Assumptions (UA)
  Detects: Project practices + Tech Stack Skills + Context7 / Academic-Papers MCP pins
         │
         ├──► TIER 0: Express / Nano (ARS < 0.20 — typo, config tweak, isolated 1-file fix)
         │      [SKIP] Layers 1, 2, Worktrees, writing-plans
         │      [RUN]  Inline edit + targeted test + diff verification
         │
         ├──► TIER 1: Standard Bugfix / Small Feature (1–3 files, single module, clear spec)
         │      [SKIP] Layer 1 Gstack framing, Layer 2 Multi-Unit Bolt DAG, Parallel Worktrees
         │      [RUN]  Scoped Stack Loadout + Superpowers `systematic-debugging` / inline TDD + `/gstack-verify`
         │
         ├──► TIER 2: Scoped Feature / Refactor (Single unit, medium risk or new interface)
         │      [SKIP] Layer 2 Multi-Unit DAG
         │      [RUN]  `/gstack-plan-eng-review` + Stack Loadout -> Single isolated Bolt Control worktree
         │             -> Superpowers TDD + fresh-context `reviewer` -> `/gstack-review` -> PR / Merge Gate
         │
         └──► TIER 3: Full Multi-Unit Bolt Wave (High CSU/IAE, cross-module feature, epic, MVP)
                │
                ▼
[Layer 1: Upfront Framing & Architecture — Interactive (`garrytan/gstack` v1.99.5.0)]
  /gstack-office-hours -> /gstack-plan-ceo-review -> /gstack-plan-eng-review
  + Stack Verification Pass via `context7` / `academic-papers` / `searxng`
                │
                ▼
[Layer 2: Unit DAG, Wave 0 Contracts & Bolt Schedule — Interactive -> Freeze Gate (`awslabs/aidlc-workflows` v2.11.4)]
  /aidlc-contract-design   -> Wave 0 shared interfaces/schemas/test-stubs
  /aidlc-units-generation  -> `unit-of-work.md` + `unit-of-work-dependency.md` (fenced YAML DAG + `touchSet` + Unit Stack Loadout)
  /aidlc-delivery-planning -> `bolt-plan.md` (sequenced Bolt waves + walking skeleton + per-unit model tier)
                │
                ▼  (Human freezes Bolt Plan; Wave 0 contracts land on integration branch as read-only for Wave 1+)
[Layer 3: Hands-Off Parallel Worktree Execution (`bolt-control` + `obra/superpowers` v7.0.2)]
  `bc_plan_from_bolt` launches parallel unit worktrees (serialized Git via `GitMutex`):
    • Per-Worktree Runtime Isolation: `JOB_SLOT`, `PORT_OFFSET`, isolated `TEST_DB_NAME` & `TMPDIR`
    • Scoped Unit Loadout Injection: only the unit's assigned stack/domain skills, practice docs, and Context7 IDs
    • Live Pre-Write Guard: rejects edits outside `touchSet`, edits to frozen Wave 0 contracts, or deletion of acceptance tests
    • Cost & Loop Circuit Breaker: auto-pauses at `maxRepairLoops` (3) or `maxCostUsd`
    • Research-Before-Blocked Inbox: `bc_report(status: "blocked")` requires `category` + `researchAttempted` evidence;
      pauses ONLY that unit worktree and notifies main session (`bc_answer` resumes it) while sibling units keep building
                │
                ▼  (Per worktree as Superpowers TDD passes)
[Layer 4: Spec-Drift Check, Gstack QA & Compound Learnings -> Owner Merge Gate]
  • Fresh-context `reviewer` subagent (on `planning-review` model pin) checks `git diff` against immutable unit spec
  • Chains `/gstack-review` -> `/gstack-qa-only` -> `/gstack-verify` -> `/gstack-document-release` with stack-specific checklists
  • Appends 3-line `Wave Learning` receipt for downstream wave jobs
  • Stops at `ready_to_merge` / PR creation for owner approval
```

## Success Criteria

1. **Standalone Open-Source Repo:** `buhagee/bolt-control` is created on GitHub as a clean public MIT repository forked/derived from `nigel-dev/opencode-mission-control` with full upstream attribution and passing CI/tests.
2. **Layer 0 Adaptive Composer (`composer.ts` + `bolt-compose` skill):** Deterministically computes the 5-axis ARS score (`IAE`, `CSU`, `VE`, `R`, `UA`), selects Tier 0–3, generates the EXECUTE/SKIP stage grid, and supports in-flight tier promotion when scope expands.
3. **Stack & Domain Loadout Resolver (`stack-loadout.ts`):** Detects repo manifests and `docs/practices/`, maps units to scoped skills and MCPs (`context7`, `academic-papers`, stack skills), and injects the loadout into each unit's session instructions.
4. **Layer 2 AI-DLC DAG Compiler & Wave 0 Freeze (`aidlc-compiler.ts`):** Parses AI-DLC's fenced YAML unit dependency block, validates acyclic dependencies and disjoint `touchSet` globs, enforces Wave 0 contract freeze, and compiles directly into executable Bolt Control plan jobs.
5. **Layer 3 Safeguards (`touchset-guard.ts`, `research-guard.ts`, `runtime-isolation.ts`, `model-matrix.ts`, `circuit-breaker.ts`):**
   - Live tool hook blocks writes outside `touchSet`, writes to frozen Wave 0 contracts, or deletion of acceptance tests.
   - `mc_report(status: "blocked")` rejects technical escalations that lack `researchAttempted` evidence and accepts valid escalations (`product_decision`, `contract_conflict`, `protected_path`, `repair_exhausted`) without halting sibling worktrees.
   - Each worktree receives isolated `JOB_SLOT`, `PORT_OFFSET`, `TEST_DB_NAME`, and resolved `ModelMatrix` model (`planning-review` vs `implementation-research` vs explicit per-job override).
   - Circuit breaker pauses a job when repair loops or cost limits are exceeded.
6. **Layer 4 Spec-Drift, Gstack QA & Compound Learnings (`qa-chain.ts`, `wave-learnings.ts`):** Requires fresh-context spec-drift verification + Layer 4 Gstack QA chain before `ready_to_merge`, and propagates wave learnings to downstream dependent units.
7. **Platform Integration:** Installed and wired into `qacey_platform`'s tracked OpenCode v2 configuration (`infrastructure/opencode/config/opencode.json`).
